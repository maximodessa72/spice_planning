### 3. ✅ Аналитика по продажам → Новые метрики
**Что добавлено:**
- **3.1** Метрика: "Позиций с остатком < плана" — количество позиций на начало месяца с недостаточным остатком
- **3.2** Метрика: "Позиций с остатком < 50% плана" — критически низкие остатки
- График динамики этих метрик по 12 месяцам

**Как работает:**
1. Для каждого месяца (mi=0..11) анализируется остаток на начало месяца
2. Сравнивается с планом продаж (из `sales_plan_base`)
3. Используется пропорциональная оценка остатка по позициям на основе их доли в плане группы
4. Подсчитывается количество позиций с недостаточным остатком

**Визуализация:**
- 3 метрики для текущего месяца (вверху)
- График с двумя линиями: "Остаток < план" и "Остаток < 50% плана"

**Локация в коде:** `app.py`, строки ~2735-2920

### 4. ✅ Импорт данных по закупкам → Улучшение интерфейса
**Что изменилось:**

#### 4.1 Переход на закладки (как в импорте продаж)
- Вместо двух отдельных блоков "Шаг 1" и "Шаг 2" теперь **две вкладки** (`st.tabs`)
- Вкладка 1: "📦 Остатки из программы"
- Вкладка 2: "📊 Планы закупок"

#### 4.2 Новый формат загрузки планов закупок
**Старый формат:**
- Скачивание шаблона с колонками: Группа | Позиция | План (текущий) | План (новый) | Сезонная
- Обновление колонки "План (новый)"
- Загрузка обновлённого шаблона

**Новый формат:**
- Простой двухколоночный файл: **Название позиции | Количество**
- Строки с заголовками групп имеют NaN во второй колонке и пропускаются
- Формат полностью аналогичен импорту продаж

**Пример нового формата:**
```
Группа / Позиция       | (пусто)
1. Єгипет (трави)      | (пусто)
Базилік зелень (В)     | 4903
Базилік зелень (С)     | 505
```

**Преимущества:**
- Единообразие с импортом продаж
- Меньше колонок — проще работать
- Не нужно скачивать шаблон — можно просто подготовить файл в нужном формате

**Локация в коде:** `app.py`, строки ~553-853

## 📝 Примечания

### Аналитика продаж - методология расчёта
Для метрик 3.1 и 3.2 используется **пропорциональная оценка** остатка по позициям:
- Берётся общий остаток группы на начало месяца (`bal_start`)
- Распределяется пропорционально плану продаж каждой позиции
- Формула: `item_stock_estimate = group_stock * (item_plan / total_group_plan)`

**Ограничение:** Это упрощённая оценка, т.к. система планирования работает на уровне групп, а не отдельных позиций.

### Импорт планов закупок - обработка сезонных позиций
При загрузке нового формата:
- Сезонные позиции **не обновляются** (как и в старом формате)
- В таблице изменений для сезонных показывается "не меняется"
- Это обеспечивает сохранность сезонной логики

## 🚀 Что дальше (на паузе)

### 3.3 Оборачиваемость по группам
**Предложенная логика:**
- Оборачиваемость (мес) = Средний остаток / Средний план продаж
- Цветовая кодировка: < 2 мес (быстро) | 2-4 мес (норма) | > 4 мес (медленно)

### 3.4 Рекомендации по корректировке планов
**Предложенная логика:**
- Оборачиваемость < 1.5 мес → "Увеличить закупки"
- Оборачиваемость > 6 мес → "Снизить закупки"
- Буфер < 1.0 в будущем → "Критический буфер"
- Остаток < 50% плана → "Недостаточный запас"

Эти блоки требуют дополнительного обдумывания логики перед реализацией.
