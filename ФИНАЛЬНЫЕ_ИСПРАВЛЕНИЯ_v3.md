# ФИНАЛЬНЫЕ ИСПРАВЛЕНИЯ v3: Фиксированные заказы НЕ пересчитываются

## НАЙДЕНА И ИСПРАВЛЕНА ПРОБЛЕМА!

### Симптом:
При редактировании фиксированного заказа (изменение только недели):
- ✅ В приложении килограммы позиций остаются прежними
- ❌ В Excel килограммы позиций меняются (новая балансировка)

### Причина:

**При сохранении формы редактирования:**
Если позиция имела `new_weight = 0`, её `in_transit[mi]` **удалялся** (строки 1498-1500 старого кода):
```python
else:
    # Удаляем позицию если вес = 0
    if "in_transit" in item and editing_mi in item["in_transit"]:
        del item["in_transit"][editing_mi]
```

**При пересчёте симуляции (simulation.py строка 306):**
```python
is_fixed = i in group["in_transit"] and all(i in it.get("in_transit", {}) for it in group["items"])
```

Заказ считается фиксированным только если **ВСЕ позиции** имеют `in_transit[i]`.

Если хотя бы одна позиция не имеет `in_transit[i]` → заказ становится **частично фиксированным** → эта позиция пересчитывается через балансировку (строки 320-322).

**В Excel (excel_export.py строка 466):**
```python
if r["ia"][item["name"]] > 0:
    c.value = int(r["ia"][item["name"]])
```

Берутся данные из `ia` (пересчитанные), а не из оригинальных `in_transit`.

```

   ↓

   ↓

   ↓
4. simulation.py проверяет:
   is_fixed = all(i in it.get("in_transit", {}) for it in group["items"])
   → TRUE (все позиции имеют in_transit[i])
   ↓
5. Строка 309: if arrive > 0 and not is_fixed:
   → НЕ выполняется (заказ фиксированный)
   ↓
6. Килограммы позиций остаются из in_transit (строки 298-299)
   ia[it["name"]] = it["in_transit"][i]
   ↓
7. Excel показывает правильные килограммы из ia ✅
```
